# Step 3: Access verification

Prove a working text route for every outlet the collection gate says must be
collected, *before* enumeration or collection begins. Consumes the gate file
(step 2); produces the access register that step 4 (enumeration) and step 5
(extraction) depend on.

The no-cop-out rule bites here: a mass-tier outlet with no working route is
a blocker to solve (alternate route, permission request, licensed access) —
never a footnote. A country's collection cannot start until every mass row
has a verified route; substantial rows should be verified before their
collection starts but do not block the country.

## Output artifact

`data/<country>/access-register-v1.csv`. The input is the derived gate file
(`collection-gate-v1.csv`, regenerated by
`data/scripts/derive_collection_gate.py`): every `required`,
`required-baseline`, and `required-representative` row must be verified and
gates the country; `blocking-unresolved` rows must be resolved or escalated;
`optional` rows are verified opportunistically before their collection.
Columns:

| column | content |
| --- | --- |
| `outlet` | matches the census row |
| `tier` | from the frozen census |
| `primary_route` | `direct` / `wayback` / `pdf` / `transcript` / `api` / `licensed` / `permission-pending` / `none` |
| `fallback_route` | second route if primary fails mid-collection |
| `test_url` | one real event-window article URL actually fetched |
| `test_result` | `ok` / `partial` (truncated/paywall-cut) / `fail`, with date |
| `event_window_coverage` | does the route reach Sep 2024 content? (Wayback capture density, archive depth) |
| `robots_tdm_status` | robots.txt and TDM-reservation stance at check time, with the caveat that archival routes have their own terms |
| `paywall` | none / metered / soft / hard, and whether the archive route bypasses it *for the event window* |
| `blocker` | yes/no; if yes, the resolution plan and owner |
| `notes` | domain changes, rebrand aliases, JS-rendering, rate limits |

Plus `access-notes.md`: per-country narrative of the hard cases, tested
commands, and any permission correspondence.

## Procedure

1. **Enumerate identity first.** Before testing routes, pin down every
   domain and brand alias the outlet used *during the event window* —
   census work has already caught three traps: Al-Manar's US domain seizure
   (multiple domain variants), MSNBC→MS NOW (msnbc.com redirects), Noticias
   Univision→N+ Univision (Jan 2026 rebrand; event-era URLs are legacy).
   The collection target is the 2024 identity, not today's.
2. **Test the direct route** with one known event article (from the old
   corpus manifests or a quick GDELT domain query): fetch, confirm the body
   text is in the response (not JS-rendered stub), note robots/TDM stance.
3. **Test the archive route regardless of whether direct works** — Wayback
   CDX per domain for Sep 15–Oct 17 2024: capture density per day, and one
   full article fetch from a capture. The archive route is preferred even
   when direct works, because it preserves day-of versions (headline edits,
   live blogs) — a project requirement, not just a fallback. (Validated:
   al-akhbar.com had ~2,158 unique captured URLs in Sep 17–25 alone.)
4. **Map the paywall.** For metered/soft paywalls (Spiegel+, Zeit+, NYT,
   WaPo), test whether day-of Wayback captures contain full text.
   Hard paywalls (WSJ, Bild+ content) go to `licensed` or
   `permission-pending` with a named plan (ProQuest TDM, publisher API,
   subscription + terms check) — collection of those bodies waits for the
   route, but headline/standfirst capture may still be permitted.
5. **TV outlets get a transcript plan.** The census collects an outlet's
   web text, but for TV mass outlets record explicitly which broadcast
   surfaces exist: transcript pages (CNN, PBS), YouTube archives of
   bulletins (LBCI, MTV, Al Jadeed — check event-week uploads survive),
   subtitle files. Web-text-only is acceptable if documented on the row.
6. **Respect stated restrictions and document the decision.** Al Jazeera's
   robots/TDM notice (flagged since the original audit) means: no automated
   direct scraping; the row's plan is (a) documented archive route,
   (b) permission request, or (c) exclusion with the census consequence
   stated (its Lebanon row is candidate-mass — exclusion would have to be
   escalated, not silently absorbed).
7. **Wire/context rows:** verify one route each (apnews.com, reuters.com,
   dpa via client papers) — needed for the distribution corpus baseline.
8. **Review:** access registers get the same scoped adversarial review as
   censuses — verify the test fetches are reproducible, the robots readings
   accurate, and no mass row's blocker is hand-waved.

## Route-testing toolkit (validated in this project)

- Wayback CDX: `https://web.archive.org/cdx/search/cdx?url=<domain>&matchType=domain&from=20240915&to=20241017&output=json&collapse=urlkey&filter=statuscode:200` — expect truncation on big domains; page with `&page=`.
- GDELT DOC API for event-URL discovery per domain (1 req/5s throttle;
  short non-English phrases rejected — use longer phrases).
- Direct fetches: send a real User-Agent; note JS-rendered shells
  (nbntv.me-style) where curl gets no article text — those need the
  archive route or a headless browser, which raises the effort class.
- Language/locale quirk: platform pages may render counts/dates in the
  machine's locale — record raw strings.

## Done criteria

- Every mass row: `test_result = ok` on a real event-window article via its
  primary route, and a fallback named.
- Every blocker row: written resolution plan with a decision owner — or an
  escalated exclusion decision recorded in the census notes.
- Event-window coverage confirmed (not just today's site working).
- Register reviewed.
